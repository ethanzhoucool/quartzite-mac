# Quartzite compiler and Quartus-style main window

Branch `overnight/compiler`. This file covers what was built, how it was checked, what is
still missing, and which Quartus details I could not confirm.

## What the compiler does

`Processing > Start Compilation` (Cmd-L) runs the same stages as Quartus' Compile Design
task, one at a time and off the main thread. Each stage writes Quartus-style messages
("Running Quartzite Analysis & Synthesis", "... was successful. 0 errors, 0 warnings"),
and the run ends with `Quartzite Full Compilation was successful. 0 errors, 0 warnings`.
Messages always say "Quartzite", never "Quartus". The ID column is left empty: no Quartus
message numbers were invented.

| Stage | Code | What it really does |
|---|---|---|
| Analysis & Elaboration | `CompileFlow.elaborate`, `Compiler.compile` | The existing design check (names, drivers, loops, unconnected inputs, routing warnings). Location checks moved to the Fitter. |
| Analysis & Synthesis | `Synthesis.swift`, `Logic.swift` | Builds each output's truth table gate by gate (up to 16 inputs). Minimizes each output over the inputs it actually depends on, using Quine-McCluskey prime implicants, essential primes with row and column dominance, then Petrick's method on the cyclic core. If Petrick's expansion grows past 4096 products, an exact bitset branch and bound takes over. Gives the minimal SOP, the minimal POS (from the OFF-set), Quartus-notation equations (`f = (x & z) # (w & !x & !y) # (!x & y & !z)`), textbook forms and lab gate cost. Maps to Cyclone V 6-input LUTs: one LUT per function of up to 6 inputs, Shannon decomposition on 1 or 2 variables (chosen by cost search) above that, identical LUTs shared. Packs LUTs into ALMs using the normal-mode rule (one 6-input LUT, or two LUTs of up to 5 inputs using at most 8 distinct inputs). Reports redundant gates (no fan-out, constant, pass-through, duplicate, equal to an input pin), stuck-at outputs (`Pin "o" is stuck at GND`), unused inputs (`No output dependent on input pin "x"`), product terms shared between outputs, and resource counts (`Implemented 6 device resources after synthesis - the final resource count might be different`). |
| Fitter | `Fitter.swift`, `DevicePins.swift`, `BoardPin` | Checks every location against the full 896-ball package table. Unknown balls, power or ground balls and dedicated pins are errors. Two pins on one location is an error (`Can't place multiple pins assigned to pin location ...`). Dual-purpose configuration pins give a warning. Missing locations give a critical warning (`No exact pin location assignment(s) for N pins of M total pins`) and are placed on a free I/O pin that no board resource uses. Warns when the board resource has the wrong direction (an output on a switch, say). Notes active-low KEYs and HEX segments. Assigns LUTs to ALMs and LABs (10 ALMs per LAB) deterministically. The LAB numbers are Quartzite's own and are labelled that way; they are not Quartus LABCELL coordinates. Without the open-source toolchain, routing is not done, and the messages say so. With it, the Fitter then runs yosys and nextpnr-mistral for real placement and routing (see `docs/ASSEMBLER_NOTES.md`). |
| Assembler | `CompileFlow.execute(.assembler)`, `HardwareFlow.assemble` | With the open-source toolchain: wraps nextpnr's bitstream in an 11-record .sof, reads it back, re-extracts and decodes it with mistral-cv, and checks every pin and truth-table row before writing `output_files/<entity>.sof`. It always ends with a warning that the file is experimental (see `docs/ASSEMBLER_NOTES.md`). Without the toolchain, or with Processing > Use Open-Source Fitter and Assembler off, it is skipped with the reason, the Tasks pane shows a grey dash, and nothing claims a .sof was made. |
| Timing Analysis | `TimingEstimate` | Logic depth only: the number of LUT levels on each input-to-output path. It is labelled "estimate" everywhere and states that it is not a Quartus timing analysis and gives no delays or slack. |
| EDA Netlist Writer | `NetlistWriter.swift` | Structural LUT-level Verilog laid out like Quartus' `.vo` (Design Ports Information, `// Equation(s):`, `lut_mask` in the Quartus encoding). It uses a small behavioural `qz_lcell_comb` module, so any Verilog simulator can run it without Intel's libraries. The header says it was generated by Quartzite and not by Quartus. It is exported as `simulation/quartzite/<entity>_quartzite.vo`. |

The CLI runs the same flow: `Quartzite --compile <file.qzproj> [--report]` prints the
messages and, with `--report`, the Compilation Report as Quartus `.rpt`-style ASCII tables.

### lut_mask encoding (checked against a Quartus netlist)

The encoding is bit index = dataf·32 + datae·16 + datad·8 + datac·4 + datab·2 + dataa.
A port that is not connected repeats the pattern. An inverted port reads the complement
of its variable. During development `LUTMask.mask(ports:function:)` reproduced, bit for
bit, the `lut_mask` that Quartus 18.1 wrote in a real `.vo` netlist for a 4-input
function whose inputs Quartus had placed on dataa/datab/datac/datae, all inverted. That
netlist is not part of this repository. The self-test now checks the convention directly:
each single input gives the standard pattern (`dataa` = `64'hAAAAAAAAAAAAAAAA` ...), and
the mask of an example function with Quartus-style inverted inputs matches an independent
derivation. Quartzite itself maps a function with plain inputs (dataa=w, datab=x, datac=y,
datad=z), so its masks can differ from Quartus' for the same function; the report notes this.

## Pin and device data (sources)

- DE10-Standard pins (SW0-9, KEY0-3, LEDR0-9, HEX0[0]-HEX5[6], CLOCK_50, CLOCK2_50,
  CLOCK3_50, CLOCK4_50, GPIO[0]-GPIO[35]). These come from the Terasic golden-top
  `DE10_Standard_golden_top.qsf` (github.com/ffxx283/WM8731_Audio) and were
  cross-checked against `menotti/ld labs/DE10_standard.qsf` (67 overlapping signals) and
  against the "All Package Pins" table Quartus wrote when it fitted that golden top
  (106 signals). There were 0 mismatches. The I/O standards are the golden top's
  (CLOCK3_50 2.5 V, everything else 3.3-V LVTTL), except the slide switches: the golden
  top has them at 2.5 V (their bank voltage depends on jumper JP3), but the ECE 2277 lab
  manuals assign 3.3-V LVTTL to every pin, so Quartzite does too. The exported `.qsf` and
  `_pins.qsf` write them as `set_instance_assignment -name IO_STANDARD` lines after the
  locations, as Quartus saves them. Without them Quartus compiles every pin at its 2.5 V
  default: Quartus 18.0 built an export that had none with every output at `V2P5_50OHM`.
- Package table (896 balls: location, pad, I/O bank, type) comes from the same Quartus
  17.0 Fitter report for 5CSXFC6D6F31C6. I/O banks shown in the Pin Planner and reports
  come only from this table. The Pin Planner does not show a VREF group; I have no source
  for it.
- Device totals. 41,910 ALMs and 112 DSP blocks are from Intel's *Cyclone V Device
  Overview* (683694, 2018.05.07), Table 12, member C6. Ten ALMs per LAB is from the
  *Cyclone V Device Handbook* Vol. 1 (CV-5V2, 2016.06.10). Pins 499, LABs 4,191, block
  memory bits 5,662,720, RAM blocks 553, PLLs 15, DLLs 4 and HSSI 9 are copied from
  Quartus' own Fitter Summary for this device in the golden-top report. The ALM count
  matches the Intel document.
- Message wording and report structure follow real Quartus output: the golden-top
  `.map.rpt`, `.fit.rpt`, `.asm.rpt`, `.eda.rpt` and `.flow.rpt` (Quartus Prime 17.0
  Standard), plus Intel's "Quartus Prime Introduction Using Verilog Designs" (for
  Quartus 18.0) screenshots of the Tasks pane, Messages window and Compilation Report.

## Main window (Quartus Prime 18.1 look)

- **Toolbar** (Quartus order): New, Open, Save | Cut, Copy, Paste | Undo, Redo |
  top-level entity | Assignment Editor, Pin Planner | Stop Processing, Start Compilation
  (accent play button), Start Analysis & Elaboration, Start Analysis & Synthesis, Start
  Fitter, Start Assembler (disabled, with an explanation), Start Timing Analyzer (labelled
  as an estimate) | Compilation Report | Programmer (explains that programming happens in
  Quartus at the lab). Run Functional Simulation and Export Quartus Project sit at the far
  right because they are Quartzite workflow steps, not Quartus toolbar items.
- **Menus**: File, Edit, View (Utility Windows: Project Navigator Opt-0, Tasks Opt-4,
  Messages Opt-3), Project, Assignments, Processing (Stop Processing Shift-Cmd-C, Start
  Compilation Cmd-L, Start submenu with Analysis & Synthesis Cmd-K, Compilation Report
  Cmd-R), Tools, plus the system Window and Help menus.
  - Fixed: Cmd-K used to run Analysis & Elaboration. In Quartus, Ctrl+K is Start Analysis
    & Synthesis.
  - Moved: Run Functional Simulation went from Cmd-R to Opt-Cmd-R, so Cmd-R can be
    Compilation Report.
  - Added: Assignment Editor Shift-Cmd-A, Open Project Cmd-J.
  - Items that are not implemented (Add/Remove Files, Revisions, Netlist Viewers, Start
    Assembler) are disabled and say why.
- **Tasks pane**:
  - The "Compilation" flow tree is Compile Design > Analysis & Synthesis (Edit Settings
    disabled, View Report, Analysis & Elaboration), Fitter (Place & Route), Assembler
    (Generate programming files), Timing Analysis and EDA Netlist Writer. Each has View
    Report. Program Device (Open Programmer) sits at the bottom.
  - Rows show a spinner, green check, warning, red X or grey dash, plus elapsed time.
    Double-click runs a stage. Stages reuse up-to-date earlier results, otherwise they run
    their prerequisites first.
  - A second flow, "Lab Flow (Quartzite)", lists pins, compile, simulate, export and
    program.
- **Messages pane**:
  - Toggle filters All / Error / Critical Warning / Warning / Info / Suppressed, with
    counts. Suppressed is always 0 and disabled, because Quartzite suppresses nothing.
  - A `<<Filter>>` field, Find... and Find Next.
  - Type | ID | Message columns, with expandable sub-messages in Quartus colours (green
    Info, blue Warning, purple Critical Warning, red Error).
  - System and Processing tabs. Double-clicking a message locates its symbol in the
    schematic.
- **Compilation Report**:
  - A Table of Contents tree: Flow Summary, Flow Settings, Flow Elapsed Time, Flow OS
    Summary, a folder per stage, then Flow Messages and Flow Suppressed Messages.
  - Analysis & Synthesis folder: Summary, Settings, Source Files Read, Resource Usage
    Summary, Resource Utilization by Entity, Equations (LUT masks), Minimized Logic, Gates
    Removed During Synthesis, Messages.
  - Fitter folder: Summary, Settings, Pin-Out File, a Resource Section (Fitter Resource
    Usage Summary, Input Pins, Output Pins, I/O Bank Usage, Logic Placement), Messages.
  - Assembler (skipped), Timing Analyzer (estimate), and EDA Netlist Writer (with the
    netlist text and Save Netlist...).
  - The tables follow Quartus' two-column style under the blue section header. File >
    Save Compilation Report as Text writes the `.rpt`-style text.
- **Pin Planner**: the board view now has HEX0-HEX5 with clickable segments (they light,
  active low, in play mode). The All Pins table has Node Name, Direction, Location, I/O
  Bank, Fitter Location, Board I/O Standard and Board Resource. **Assignment Editor**
  tab: Status | From | To | Assignment Name | Value | Enabled | Comment, plus a
  `<<new>>` row for nodes that have no location yet. A status bar at the bottom shows
  progress % and elapsed time, as in Quartus.

## Verification

```
swift build                                          # clean
./.build/debug/Quartzite --selftest                  # ALL PASSED (81 compiler checks plus the existing ones)
./.build/debug/Quartzite --export-suite /tmp/qz-comp-suite-final
python3 ci/bdf_check.py /tmp/qz-comp-suite-final/*   # PASS for every exported design
./build_app.sh                                       # builds Quartzite.app
./.build/debug/Quartzite --compile ci/designs/example_sop.qzproj   # 0 errors, 0 warnings
./.build/debug/Quartzite --snapshot-window ci/designs/example_sop.qzproj /tmp/qz-shots
```

The compiler self-tests (`CompilerSelfTest.swift`) cover:

- lut_mask convention: single-input patterns, an inverted-input mask against an independent
  derivation, and local-table replication against the general encoder.
- The example function Σm(2,3,6,7,9,13,14): minimal SOP and POS, Quartus notation, cost
  7/14; Petrick's method on a cyclic cover; GND/VCC constants.
- 300 random functions:
  - the cover always equals the function (3-10 inputs);
  - for 200 functions of 3-4 inputs, the term count equals a brute-force minimum over all
    prime subsets;
  - exactness is reported (5-7 inputs dense, 8-10 sparse).
- 24 random 4-10 input functions mapped to LUTs. They match the truth table, no LUT has
  more than 6 inputs, and functions of 6 or fewer inputs use one LUT.
- ALM packing rules (4+4, 5+3, 5+5 sharing 2 inputs; 5+5 independent needs 2 ALMs; a
  6-input LUT is alone).
- For every design in `TestDesigns.all`:
  - full compilation succeeds;
  - the in-memory LUT network and the written `.vo` text (parsed and evaluated) both
    reproduce the schematic simulation on every row;
  - the Assembler is skipped;
  - the run ends with the Full Compilation line;
  - the report renders.
- The example design: one 4-input LUT in one ALM, 6 device resources, 0 errors and 0 warnings.
- Fitter errors and warnings:
  - errors: nonexistent ball, GND ball, two pins on one location;
  - critical warning: missing location;
  - warning: output on a switch.
- Synthesis: `AND(a, !a)` stuck at GND, `OR(b, b)` pass-through, `o2 = b` needs no LUT.
- Package and board tables: 896 balls, 457 user I/O, every board pin is a user I/O, no
  duplicates, spot checks, banks.

### Timing of a multi-file design

`addsub4_display` (`TestDesigns.addSub4Display`, also `ci/designs/addsub4_display.qzproj`)
is the size reference for hierarchical designs: four sheets (HA, FA, AddSub4 and the top),
three 7447s, 9 inputs and 26 outputs, 12 of which depend on all 9 inputs. The self-test
prints its timing. Measured on an Apple Silicon Mac, 2026-10-22:

| Build | Analysis & Synthesis | Full flow (self-test) | `--compile` wall time | Flatten + 512-row simulation |
|---|---|---|---|---|
| debug | 2.67 s | 3.76 s | 2.2 s | 188 ms |
| release | 0.08 s | 0.19 s | 0.14 s | 44 ms |

Outputs with 9 to 12 support inputs use `Minimizer.wideLimits`: branch and bound stops
after 20,000 nodes, more than 1500 primes means a greedy cover, and Petrick's method gives
up beyond 256 products (4096 otherwise). Before that Petrick limit, the 9-input HEX0
segments spent about 1 s each (release) and 10 s each (debug) in Petrick's absorption step
before falling back to branch and bound; the covers found are the same size with either
limit.

`--snapshot-window` renders the real `ContentView` offscreen with `cacheDisplay`; this
works without screen-recording permission. It renders after a full compilation, for each
tab, and once mid-run through the asynchronous pipeline. The live run reached
`Analysis & Synthesis=succeeded, Fitter=succeeded, Assembler=skipped, Timing
Analyzer=succeeded, EDA Netlist Writer=succeeded`, ended with "Quartzite Full Compilation
was successful. 0 errors, 0 warnings", and switched to the Compilation Report tab.

## Known gaps

- No .sof, no routing, no delays. Logic placement is logical (LAB n, ALM m), not a Quartus
  floorplan. Quartus may pack ALMs differently and may add cells (Quartus netlists often contain an
  extra `~QUARTUS_CREATED_GND~I` cell), so the ALM count is labelled an estimate after synthesis.
- LUT port assignment and input inversions differ from Quartus, so masks differ even when
  the function is the same.
- Minimization is per output. Shared product terms between outputs are reported, but
  multi-output minimization (shared implicants) is not done. Above 12 inputs per output,
  minimization is skipped; LUT mapping still works up to 16 inputs. Dense random 9-10
  input functions can hit the search limit; the cover is then marked "best found, may not
  be minimal".
- Fan-out figures (total, average) use Quartzite's own node count; Quartus' denominator
  for "Average fan-out" is not known.
- When the Fitter places an unassigned pin, Quartzite chooses the pin (a free I/O pin with
  no board resource). Quartus chooses its own.
- The Linux CI build (swift:5.10) could not be run here because there is no docker. The
  new core files are Foundation-only and were audited (for example, no `as NSString`
  bridging).
- The exported README_LAB.txt (Exporters.swift, editor-owned) does not mention the new
  `simulation/quartzite` netlist yet.

## Quartus behaviours I could not confirm

- These shortcuts are from memory, because Intel's online shortcut page now returns 404:
  Compilation Report Ctrl+R, Assignment Editor Ctrl+Shift+A, Stop Processing
  Ctrl+Shift+C, Open Project Ctrl+J, and View > Utility Windows Alt+0 / Alt+4 / Alt+3.
  Intel documentation confirms Ctrl+L (Start Compilation) and Ctrl+K (Start Analysis &
  Synthesis). Redo stays Shift-Cmd-Z (the macOS convention) rather than Quartus' Ctrl+Y.
- The exact set of Messages filter buttons in 18.1. Screenshots show All, Error, Critical
  Warning, Warning and one more icon. I implemented the six the task lists.
- Message wording is copied from Quartus 17.0 Standard reports, not 18.1 Lite. 18.1 calls
  TimeQuest the "Timing Analyzer". Lines with no Quartus equivalent (minimized logic,
  redundant gates, routing not performed) are worded as Quartzite messages.
- HPS-bank balls (6A/6B/7A-7D) are accepted as user I/O because Quartus' report lists
  them as unused inputs. Whether a plain FPGA design can use them was not checked.
